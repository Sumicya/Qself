## 已确认的产品范围

- 仅精简版，需要功能再增补；撤销此前“精简版 + 完整版”的双版本方案。

- 先重构模块设置页。
- 最新要求：常规页面使用 Material 3 Expressive，玻璃仅用于小窗、局部弹层等场景；替代此前的设置页玻璃核心方向。
- 只保证用户主力环境，旧 QQ/TIM/其他加载后端不作为本阶段验收目标。删除兼容实现前仍须检查共享依赖。
- 原则：简化、原生化、自由化、现代化。
- 旧分支个人功能集作为候选输入，不能将其所有实验功能直接认定为首版必装项。

## 稳定性与隐私目标

用户希望增强隐蔽性，降低被检测后踢下线和反复登录的风险。

工程上以最小注入、最少非必要宿主改动、移除非必要遥测、可控诊断和异常隔离为初步方向，不承诺无法被检测或永久保持登录。

- 未取得提示和对照证据前，不把掉线直接归因于 Qself 或某个第三方模块。
- 不通过隐藏安全提示、吞掉退出登录事件或伪造登录成功来声称问题解决。
- 不修改或收集登录凭据、验证码、cookie、会话票据。
- 不通过反复自动登录、反复触发安全挑战做验证。
- 未验证的网络拦截不作为默认保护措施。
- 诊断默认最少量、本地、脱敏；不得要求用户提交包含聊天正文、账号凭据的完整日志。

## 当前仍待解决的问题（编号恢复后的复查）

- 最高优先：`RiskReportInterceptor` 仍按前缀拦截，MSF 只取首个同名方法，未确认返回语义便赋 null。上一批只为旧 `ChannelProxyHook` 补了新 QQ 版本保护，不能混称两者都修好了；尚无掉线因果证据。
- 诊断只覆盖三处 Java 入口与两类命令，不知道服务器是否接收；128 行在高频情况下很快覆盖。跨夜排查宜增加有界的按时间段统计和关键事件保留，并测量采集开销。
- 旧 `DiagLog` 仍是单独的普通文本写入路径，没有自己的总开关/统一脱敏，而且共享 SimpleDateFormat 缺少线程保护。移除 AppCenter 不代表旧日志全部整改完成。
- 本批处理精简注册与配置承接；旧实现源文件的进一步物理拆除仍需依赖审计，不能与停止加载混称。
- CI 测试签名还不是固定发行签名；安装器能处理安装限制，不等于已解决签名管理。
- 真机的 Hook 覆盖、后台待机、耗电和登录保持尚待验证；自动热重载目前保持关闭。
