# 能力合并，不再以大量停用替代精简

2026-09-12。用户纠正：先合并同类能力、重复入口和实现，不是继续削减功能。

## 本批实际修改

1. 删除旧的 `config/simplified-features.txt`。使用一个 `config/feature-catalog.tsv` 同时生成 Hook/UI 注册表及设置路由；不再另维护首页、白名单和功能分组三份清单。恢复净化、复制/分享、输入、消息尾注、好友/群、通知及系统打开方式等能力。实验性身份/设备伪装和未验证写操作没有一并放开。
2. 同类能力收进统一净化、消息工具、消息标注、好友与群工具、通知管理、外观调整、媒体与系统工具、维护与诊断页面。页面内按场景排列子项，直接使用原始 provider 的开关/配置页面，不用代理包装破坏 Hook 初始化。首页、搜索、状态页长按和深链接都指向相同规范路径。
3. 删除 `AdPurifySuite` 空 Hook/批量总开关。五个广告能力进入统一净化的广告分区，单独选择，不再借总开关联动掩盖混合状态。
4. **实际去重消息渲染**：NoSeq 提示不再维护另一套气泡布局，删除约 200 行重复视图实现。ID/时间与 NoSeq 共用一个尾注渲染器、相同布局 ID 和状态仲裁；发送异常提示优先，灰字不加尾注，复用气泡时清掉旧文本/tag/点击状态。原配置键不变。
5. **实际合并消息菜单安装**：复读、复制文字/卡片/图片/Markdown、语音保存和图片信息共用菜单分发器。按 `Method` 而非子类名去重安装，继承同一菜单方法不重复插入菜单项；按当前接收者类型路由，安装失败允许重试，并发安装只执行一次。
6. 恢复的输入、系统打开方式和卡片转换子项接回共享 dispatcher。特定“小程序转链接”优先于通用“卡片文本化”，不让通用规则先吞掉特定规则。
7. 不批量重写开关值；恢复的能力继续读取自己的原配置。旧分类保存状态按功能 ID 转入合并页，无 ID 的失效分类退回目录而不是崩溃。

## 测试

新增尾注所有开关组合/状态转换、继承方法去重、失败重试、并发安装、目录唯一性、路由防御拷贝、坏目录拒绝及实际 DSL 树覆盖测试。保留设置实际容器/大字/深浅色测试。

这批完成目录与消息处理的合并；通知等跨不同宿主接口的具体 Hook 仍保留独立实现，不把“同一设置页”冒称为所有底层 Hook 已统一。
